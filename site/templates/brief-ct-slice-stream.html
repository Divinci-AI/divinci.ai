Stopping a CT scan at the organ's edge: a benchmark you can plug a model into

Today the X-ray beam stays on past the organ that was asked for, because nobody can read the images fast enough to stop it. We built a test rig for the alternative. It replays real CT scans one slice at a time, at scanner speed and at simulated doses down to 2%, and scores whether a model switches the beam off after the organ without cutting it short.

What this is and isn't. An offline feasibility test on {{ v.scans_total }} public, de-identified research CTs. No scanner is involved, no private patient data is used, and nothing here is a clinical claim. The model in it is a deliberately simple baseline: its job is to prove the rig works and to set a number to beat, not to be the answer. The results are signed with a throwaway demo key, never a Divinci platform key.

How the test works

  1. Real scans, labelled organs. {{ v.scans_total }} portal-venous abdominal CTs with expert spleen outlines, from the Medical Segmentation Decathlon. We use real images, not generated ones. Only the dose is simulated.
  2. A dose ladder. Every slice is re-projected into raw detector data. We add the photon noise a scan at 50%, 25%, 10%, 5% and 2% of the original dose would have carried, then reconstruct it. Noise grows as expected, roughly with 1/√dose.
  3. A stream, not a volume. Slices are replayed from the top of the abdomen downward, one at a time. At each slice the model sees only what has already arrived (that slice and the one before) and outputs one number: how confident it is that the organ is in view.
  4. A fixed stop rule. Organ entered is called after two confident slices. Organ exited is called once confidence has stayed low for {{ v.exit_sustain }} mm, and the beam then stays on for a safety margin before stopping. If the model never makes a confident exit call, the scan simply finishes as planned. That happened on {{ v.fallback_pct }} of scans.
  5. Scoring against the outline. Was the whole organ covered? If not, by how much was it missed? How far past the organ did the beam stay on? How long did the model take per slice? Every scan is scored by a model that never saw it (5-fold cross-validation by patient).

What we found

1. The baseline is not safe, and the benchmark says so plainly.

At full dose {{ v.truncated }} of {{ v.scans }} scans were cut short, by {{ v.misses }} mm. Four of those misses are the thin tip of the organ. One is a mid-organ collapse in confidence, and that single scan forces the {{ v.margin_full }} mm margin. A clinical system has to get the far edge right every time, so a model worth deploying should drive "margin for 100%" toward the slice thickness, not just raise the average.

2. Coarse edge detection tolerates very low dose.

Coverage barely moves from 100% down to 2% simulated dose ({{ v.complete }} to {{ v.low_complete }}). The baseline looks at a heavily downsampled slice, which averages the noise away. That supports the idea of an ultra-low-dose pass that only locates organ boundaries before the diagnostic pass. It does not show that a diagnosis survives low dose, and our simulation is a simplified parallel-beam approximation.

3. Speed is not where this fails.

The model answers in {{ v.lat_p50 }} ms (median) on one CPU core, about {{ v.headroom }}× inside the tightest per-slice budget. What this benchmark does not yet time is the rest of the loop: slice reconstruction, transfer off the scanner, and the controller's response. Those need scanner-side access to measure.

4. Training on noisy data did not help this model.

Training across every dose level was, if anything, slightly worse at 2% than training on full dose alone. A result like that is only visible when every variant runs through the same fixed rig.

Plugging in a better model

The contract is deliberately small. A model receives one slice as it arrives, plus the slice before it, and returns a confidence between 0 and 1. The stop rule, the scoring, the cross-validation folds and the signing stay fixed, so any two models are compared on identical terms. Natural next tracks, in the order we would build them:

  • More organs, using public scans with TotalSegmentator outlines, including the kidneys, adrenals and liver.
  • Paediatric scans. This is where the dose saving matters most and public data is thinnest.
  • End-to-end timing, including reconstruction and controller latency, once there is access to a scanner's live image stream.
  • Findings, not just edges: triggers for delayed or repeat scans, such as a vessel not filling or an injured organ. Each would be scored the same way, against radiologist ground truth.

The signed record

The run is recorded as a manifest covering the dataset hash, the hash of every code file, the configuration, the latency figures and the full results. It is signed with Ed25519 over canonical JSON, the same signing contract Divinci's TrustBench uses for AI evaluations. Change any number in it and verification fails.

Method notes

  • Data. Medical Segmentation Decathlon, Task 09 (spleen), training split: {{ v.scans_total }} CTs from Memorial Sloan Kettering Cancer Center, CC-BY-SA 4.0 (Antonelli et al., Nature Communications 2022). {{ v.excluded }} is excluded from scoring because its spleen runs off the bottom of the scan, so the true edge is unknown. Slice thickness ranges from 1.5 to 8 mm.
  • Dose simulation. Parallel-beam forward projection over 180 angles and projection-domain noise insertion, calibrated so spleen noise follows about 1/√dose (measured about 22–29 HU at 100%, 41–44 at 25%, 96–102 at 5%), followed by filtered back-projection. It has no bowtie filter, electronic noise or scatter model.
  • Baseline model. A 48 × 48 soft-tissue-window thumbnail of the slice plus its difference from the previous slice, reduced by PCA to 64 components and passed to logistic regression. A version that added a full-resolution crop of the organ's quadrant did not do better.
  • "Past the organ" is a proxy. It measures how far the beam stayed on beyond the spleen within each scan's original range. Those scans were planned for wider clinical questions, so the {{ v.tail_cut }} figure describes the mechanism, not a dose saving for any real protocol.
